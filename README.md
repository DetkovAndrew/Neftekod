# Нефтекод — МАС поддержки решений АВТ → Гидроочистка → Блендинг

Мультиагентная система (МАС), которая получает состояние технологического процесса (АВТ → гидроочистка дизельной фракции → блендинг товарного ДТ), оценивает последствия возможных изменений режима и формирует безопасную, объяснимую рекомендацию оператору — либо мотивированно отказывается, если надёжной рекомендации нет.

Полное описание архитектуры и обоснование решений: **[ARCHITECTURE.md](./ARCHITECTURE.md)**.

Статус: система работает целиком. Детерминированная часть реализована и покрыта тестами (99 тестов): синхронизация данных, онтология тегов и цифровой P&ID, ВАК-формулы, контракты агентов, Guard. Модели качества обучены и отобраны на реальных данных с честной хронологической валидацией (**[MODEL_AUDIT.md](./MODEL_AUDIT.md)**), выбранные soft-sensor'ы подключены к Агенту качества. Оркестратор ведёт явную трассу обмена между агентами. LLM (Qwen2.5-7B через Ollama) подключена как Monitor-слой вне критического пути: она пишет комментарий к уже готовой и проверенной карточке и не влияет на решение.

На всей истории 01.2023–08.2026 (проверка раз в сутки, 1315 точек) система рекомендует действие в 50% случаев, в 32% не требует действий и в 18% мотивированно отказывается.

## Структура репозитория

```
ARCHITECTURE.md          — подробная архитектура и обоснования
MODEL_AUDIT.md            — результаты и находки обучения ML-слоя на реальных данных
config/
  control_variables.yaml — кандидатные управляющие воздействия + обоснование + confidence
  hard_constraints.yaml  — жёсткие ограничения качества/блендинга
src/neftekod_mas/
  schemas.py              — pydantic-контракты между агентами
  tags/                   — онтология тегов, цифровой P&ID граф, валидация
  data/                   — загрузка и синхронизация источников (ЛИМС/ПАК/КИП), детектор переходного режима
  quality/                — Агент качества, ВАК-формулы, якорные soft-sensor'ы
  reliability/            — Агент надёжности
  optimization/           — Агент оптимизации
  orchestrator/           — Оркестратор, шина сообщений, Guard, объяснения, LLM Monitor
  ml/                     — датасет/split/baseline GBM/модульная PI-сеть (обучены, см. MODEL_AUDIT.md)
  utils/                  — единицы измерения, логирование прогонов
scripts/
  build_tag_ontology.py   — строит config/tag_ontology.json из выданных материалов (локально, не в git)
  run_demo_cycle.py       — прогоняет один цикл принятия решения и печатает карточку рекомендации
  run_history_scan.py     — прогон по диапазону истории + офлайн-дашборд runs/dashboard.html
  cluster/                — sbatch-скрипты для кластера (обучение, сервер Ollama)
  train_quality_models.py — обучение baseline (LightGBM) и PI-сети (--model gbm|pinn)
  audit_quality_model.py  — честное сравнение кандидатов (snapshot/causal × PINN/LightGBM) по validation MAE
tests/                    — юнит-тесты (в т.ч. сверка ВАК-формул, отсутствие утечки из будущего в ML-слое)
```

Положите их в каталог рядом с проектом и укажите путь:

```bash
export NEFTEKOD_DATA_DIR=/home/acid/neftekod   # каталог с исходными файлами хакатона
```

## Запуск

```bash
# 1. Построить онтологию тегов / цифровой P&ID и калибровочные конфиги
#    (генерируют config/*.json,*.yaml локально -- это статистика/справочник,
#    не обучение модели, см. ARCHITECTURE.md §2, §6.3, §5.3)
python scripts/build_tag_ontology.py
python scripts/compute_reliability_bounds.py
python scripts/compute_control_bounds.py
python scripts/compute_kip_bounds.py
python scripts/compute_vak_formula_accuracy.py
python scripts/compute_astm_cetane_accuracy.py
python scripts/compute_joint_envelope.py

# 2. Прогнать тесты (в т.ч. сверка ВАК-формул с эталонными расчётами)
pytest -q

# 3. Прогнать один цикл принятия решения на выбранной временной точке
python scripts/run_demo_cycle.py --timestamp "2023-03-15 10:00:00"

# 4. Тот же цикл с трассой обмена агентов (кто что кому передал)
python scripts/run_demo_cycle.py --timestamp "2025-12-01 20:00:00" --trace

# 5. (Необязательно) Прогнать МАС по диапазону истории и построить офлайн-дашборд
#    -- результат в runs/dashboard.html (не в git, см. .gitignore), открывается
#    в браузере без интернета и без сервера (данные встроены в сам HTML)
python scripts/run_history_scan.py --start 2023-01-01 --end 2023-04-01 --step-hours 12
```

Демонстрационные точки на реальных данных (ТЗ п.6):

| Момент | Что показывает |
|---|---|
| `2025-12-05 03:00:00` | стабильный режим: действий не требуется, сера под наблюдением |
| `2025-12-01 20:00:00` | риск по сере: рекомендация поднять T5 с 376 до 380 °C |
| `2024-04-23 06:30:00` | пуск реактора: отказ, режим вне области применимости моделей |
| `2024-02-28 00:00:00` | сера за нормативом, но рычаг T5 уже на границе диапазона -- отказ |

## LLM Monitor (Qwen2.5-7B)

LLM **не участвует в принятии решения**: она получает уже посчитанную и проверенную Guard'ом карточку и пересказывает её оператору обычным языком (ARCHITECTURE.md §9). Без неё система работает полностью -- шаблонное объяснение остаётся основным. Каждый ответ модели проверяется: все числа и теги должны присутствовать в карточке, текст должен быть на русском; иначе комментарий отбрасывается целиком.

Поднять модель у себя (нужен GPU на 6+ ГБ; на CPU тоже работает, но медленно):

```bash
# 1. Установить Ollama (без root, в $HOME)
mkdir -p ~/ollama && curl -fsSL https://ollama.com/download/ollama-linux-amd64.tar.zst \
  | zstd -dc | tar -C ~/ollama -xf -

# 2. Запустить сервер и скачать модель (~4.7 ГБ)
~/ollama/bin/ollama serve &
~/ollama/bin/ollama pull qwen2.5:7b

# 3. Прогнать цикл с комментарием LLM
python scripts/run_demo_cycle.py --timestamp "2025-12-01 20:00:00" \
  --llm-url http://localhost:11434/v1 --llm-model qwen2.5:7b
```

На кластере Slurm (модель на выделенном узле с GPU, запросы -- через ssh-туннель):

```bash
sbatch --nodelist=<узел> scripts/cluster/ollama_serve.sbatch   # на кластере
ssh -f -N -L 11434:<узел>:11434 <login-хост>                   # на рабочей машине
```

Подойдёт любой OpenAI-совместимый сервер (vLLM, llama.cpp server) и любая модель -- адрес и имя задаются флагами `--llm-url` / `--llm-model`. Ответ Qwen2.5-7B на RTX 2060 занимает 1-5 с. Модели меньше 7B (пробовали 3B) пересказывают карточку хуже.

## Принцип, который система не нарушает никогда

> Качество и жёсткие технологические ограничения имеют приоритет над экономическим эффектом. Недопустимый режим нельзя «компенсировать» более высокой производительностью или меньшими затратами.

Реализовано как независимый Guard-слой в Оркестраторе (см. §6.5, §9 в ARCHITECTURE.md), а не как штраф в целевой функции.
