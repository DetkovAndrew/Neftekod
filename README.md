# Нефтекод — МАС поддержки решений АВТ → Гидроочистка → Блендинг

Мультиагентная система (МАС), которая получает состояние технологического процесса (АВТ → гидроочистка дизельной фракции → блендинг товарного ДТ), оценивает последствия возможных изменений режима и формирует безопасную, объяснимую рекомендацию оператору — либо мотивированно отказывается, если надёжной рекомендации нет.

Полное описание архитектуры и обоснование решений: **[ARCHITECTURE.md](./ARCHITECTURE.md)**.

Статус на текущий момент: спроектирована и реализована детерминированная часть системы (синхронизация данных, онтология тегов/цифровой P&ID, ВАК-формулы, агентные контракты). Обучение ML-моделей **не выполнялось** — согласно текущему этапу работы.

## Структура репозитория

```
ARCHITECTURE.md          — подробная архитектура и обоснования
config/
  control_variables.yaml — кандидатные управляющие воздействия + обоснование + confidence
  hard_constraints.yaml  — жёсткие ограничения качества/блендинга
src/neftekod_mas/
  schemas.py              — pydantic-контракты между агентами
  tags/                   — онтология тегов, цифровой P&ID граф, валидация
  data/                   — загрузка и синхронизация источников (ЛИМС/ПАК/КИП)
  quality/                — Агент качества + ВАК-формулы
  reliability/            — Агент надёжности
  optimization/           — Агент оптимизации
  orchestrator/           — Оркестратор, Guard, генерация объяснений
  utils/                  — единицы измерения, логирование прогонов
scripts/
  build_tag_ontology.py   — строит config/tag_ontology.json из выданных материалов (локально, не в git)
  run_demo_cycle.py       — прогоняет один цикл принятия решения и печатает карточку рекомендации
tests/                    — юнит-тесты (в т.ч. сверка ВАК-формул с примерами расчёта из материалов)
```

## Данные

Сырые материалы хакатона (`avt_tags.csv`, `242000_tags.csv`, `ЛИМСы*.xlsx`, `Выгрузка ПАК*.xlsx`, тэговые справочники, PDF) — **не входят в репозиторий** (репозиторий публичный, данные — реальная технологическая телеметрия и лабораторные результаты, предоставленные под условия хакатона). Положите их в каталог рядом с проектом и укажите путь:

```bash
export NEFTEKOD_DATA_DIR=/home/acid/neftekod   # каталог с исходными файлами хакатона
```

## Установка

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## Запуск

```bash
# 1. Построить онтологию тегов / цифровой P&ID и калибровочные конфиги
#    (генерируют config/*.json,*.yaml локально -- это статистика/справочник,
#    не обучение модели, см. ARCHITECTURE.md §2, §6.3, §5.3)
python scripts/build_tag_ontology.py
python scripts/compute_reliability_bounds.py
python scripts/compute_control_bounds.py
python scripts/compute_kip_bounds.py
python scripts/compute_vak_formula_accuracy.py

# 2. Прогнать тесты (в т.ч. сверка ВАК-формул с эталонными расчётами)
pytest -q

# 3. Прогнать один цикл принятия решения на выбранной временной точке
python scripts/run_demo_cycle.py --timestamp "2023-03-15 10:00:00"

# 4. (Необязательно) Прогнать МАС по диапазону истории и построить офлайн-дашборд
#    -- результат в runs/dashboard.html (не в git, см. .gitignore), открывается
#    в браузере без интернета и без сервера (данные встроены в сам HTML)
python scripts/run_history_scan.py --start 2023-01-01 --end 2023-04-01 --step-hours 12
```

## Принцип, который система не нарушает никогда

> Качество и жёсткие технологические ограничения имеют приоритет над экономическим эффектом. Недопустимый режим нельзя «компенсировать» более высокой производительностью или меньшими затратами.

Реализовано как независимый Guard-слой в Оркестраторе (см. §6.5, §9 в ARCHITECTURE.md), а не как штраф в целевой функции.
