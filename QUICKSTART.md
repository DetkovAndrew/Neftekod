# Нефтекод — МАС поддержки решений оператора. С чего начать

Это мультиагентная система по ТЗ хакатона: АВТ → гидроочистка → блендинг. Она берёт состояние процесса,
оценивает качество продукта и риск для оборудования, перебирает допустимые изменения режима и выдаёт
оператору либо рекомендацию с объяснением, либо мотивированный отказ.

Запускается локально, без интернета. Обучать ничего не нужно: все калибровки и справочники уже посчитаны
и лежат в `config/`.

## Что в архиве

```
QUICKSTART.md     — этот файл
README.md         — установка, запуск, LLM Monitor
ARCHITECTURE.md   — архитектура, обоснование каждого решения, ограничения (главный документ)
MODEL_AUDIT.md    — как обучались и проверялись модели качества, найденные ошибки методологии
src/, tests/      — код системы и 138 тестов
config/           — готовые конфиги: онтология тегов, ВАК-формулы, пороги, границы рычагов
scripts/          — демо-цикл, прогон по истории, обучение, скрипты для кластера
runs/             — журналы уже выполненных циклов и дашборд dashboard.html по всей истории
data/             — исходные материалы хакатона (телеметрия, ЛИМС, ПАК, справочники, схемы, ТЗ)
.git/             — полная история разработки
```

## Установка (5 минут)

Нужен Python 3.10 или новее и около 4 ГБ оперативной памяти.

```bash
cd neftekod-mas
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export NEFTEKOD_DATA_DIR=<путь к папке data из архива>
```

Проверка, что всё на месте:

```bash
pytest -q          # ожидается: 138 passed
```

## Первый запуск

```bash
# один цикл принятия решения на конкретный момент времени
python scripts/run_demo_cycle.py --timestamp "2025-12-01 20:00:00"

# то же самое, но с трассой: кто из агентов что кому передал
python scripts/run_demo_cycle.py --timestamp "2025-12-01 20:00:00" --trace
```

Четыре сценария из ТЗ п.6, все на реальных данных:

| Момент | Что видно |
|---|---|
| `2025-12-05 03:00:00` | стабильный режим: лишних действий система не предлагает |
| `2025-12-01 20:00:00` | риск по сере: рекомендация поднять T5 с 376 до 380 °C |
| `2024-04-23 06:30:00` | пуск реактора: отказ, режим вне области применимости моделей |
| `2024-02-28 00:00:00` | сера за нормативом, но рычаг уже на границе диапазона: отказ |
| `2026-02-24 00:00:00` | риск по T95: рычаг блендинга -- доля фр. 290-350 с 73.1 % до 67.1 %, Σ долей = 100 % |

Каждый цикл пишет журнал в `runs/<момент>/`: состояние процесса, оценки агентов, все кандидаты
оптимизации, трасса обмена и итоговая карточка. По нему можно проверить любое решение системы.

Прогон по истории и офлайн-дашборд (открывается двойным кликом, интернет не нужен):

```bash
python scripts/run_history_scan.py --start 2023-01-01 --end 2026-08-07 --step-hours 24
# результат: runs/dashboard.html
```

## Поднять Qwen у себя

LLM в этой системе может работать в двух режимах, и ни в одном она не считает числа сама.
**Monitor** (§9) пересказывает оператору уже посчитанную и проверенную карточку и не влияет на решение.
**Оркестратор** (§9.1, флаг `--llm-orchestrator`) ведёт сам цикл через вызовы инструментов, но
повлиять на итог может только выбором варианта из уже проверенного списка, а Guard сохраняет право
вето; при любом сбое модели отрабатывает обычный детерминированный оркестратор.

Про Monitor: Без неё всё работает: основное объяснение генерируется шаблонами.
Каждый ответ модели проверяется — числа и теги обязаны быть в карточке, текст обязан быть на русском,
иначе комментарий отбрасывается целиком.

Нужен GPU на 6+ ГБ (проверено на RTX 2060, ответ за 1–5 с). На CPU тоже работает, но медленно.

```bash
# 1. Ollama без root, в домашний каталог
mkdir -p ~/ollama
curl -fsSL https://ollama.com/download/ollama-linux-amd64.tar.zst | zstd -dc | tar -C ~/ollama -xf -

# 2. Сервер и модель (~4.7 ГБ)
~/ollama/bin/ollama serve &
~/ollama/bin/ollama pull qwen2.5:7b

# 3. Цикл с комментарием LLM
python scripts/run_demo_cycle.py --timestamp "2025-12-01 20:00:00" \
  --llm-url http://localhost:11434/v1 --llm-model qwen2.5:7b
```

Если GPU стоит на другой машине или в кластере Slurm:

```bash
sbatch --nodelist=<узел> scripts/cluster/ollama_serve.sbatch   # на кластере
ssh -f -N -L 11434:<узел>:11434 <login-хост>                   # на рабочей машине
# дальше та же команда run_demo_cycle.py с --llm-url http://localhost:11434/v1
```

Подойдёт любой OpenAI-совместимый сервер (vLLM, llama.cpp server) и любая модель: адрес и имя задаются
флагами `--llm-url` и `--llm-model`. Модели меньше 7B пересказывают карточку заметно хуже.

## Если нужно пересчитать конфиги с нуля

Обычно не нужно — всё лежит готовое в `config/`. Команды на случай, если данные поменяются
(это статистика и справочники, а не обучение моделей):

```bash
python scripts/build_tag_ontology.py
python scripts/compute_reliability_bounds.py
python scripts/compute_control_bounds.py
python scripts/compute_kip_bounds.py
python scripts/compute_vak_formula_accuracy.py
python scripts/compute_astm_cetane_accuracy.py
python scripts/compute_joint_envelope.py
python scripts/compute_blend_model.py                    # модель блендинга (§6.6)
python scripts/compute_sulfur_temperature_response.py    # калибровка серы (§6.4.1)
```

Обучение моделей качества (нужен GPU или терпение) описано в `MODEL_AUDIT.md`,
запускается через `scripts/train_quality_models.py` и `scripts/cluster/`.

## Что важно знать про ограничения

Честный список — в конце `ARCHITECTURE.md` (§13). Самое главное:

1. Влияние температуры реактора на серу теперь откалибровано по истории САМОЙ установки (отклик
   поточного анализатора Q21 на 1462 ступени температуры), и измеренная чувствительность оказалась
   в разы меньше литературной. Система берёт консервативную оценку, поэтому чаще отказывается —
   зато не обещает снижения серы, которого установка не показывает.
2. У T95 появился рычаг — доли компонентов дизельного пула АВТ (§6.6). Но он один, и его
   авторитета хватает не всегда: сдвиг доли на 1 п.п. меняет T95 продукта примерно на 0.31 °C.
3. Блендинг реализован для пула АВТ; ТОВАРНЫЙ блендинг (присадки, сторонние компоненты)
   по-прежнему только на уровне схемы — в данных нет ни их расходов, ни качества.
4. Изменение одной уставки не распространяется на связанные теги: нагрев T5 не меняет T6 и T11 в прогнозе.
5. Экономика: натуральные величины измерены, ЦЕНЫ — допущение (`config/economics.yaml`).
6. Паспортных ограничений оборудования нет; надёжность оценивается по перцентилям истории.

## Данные

Папка `data/` — материалы хакатона: телеметрия АВТ и установки 24-2000 (10-минутные ряды,
01.2023–08.2026), выгрузки ЛИМС и ПАК, справочники тегов, ВАК-формулы, технологические схемы, ТЗ
и расшифровка Q&A-сессии. Это реальные производственные данные, в публичный репозиторий они не
выкладываются (см. `.gitignore`) — поэтому они и передаются архивом.
